# Windows EXE Build Runbook

This document describes how to build and test the Windows executable for Appraze AI.

## Prerequisites (on GitHub Actions)

The build runs entirely in GitHub Actions on a `windows-latest` runner. No local Windows machine is required to produce the artifact.

## Triggering the Build

1. Go to the repository on GitHub.
2. Click the **Actions** tab.
3. In the left sidebar, select **Build Windows EXE**.
4. Click **Run workflow** (right side).
5. (Optional) Adjust the Streamlit port if needed — the default is `8501`.
6. Click the green **Run workflow** button.

The build takes approximately 5–15 minutes depending on runner load and dependency caching.

## Where the Artifact Lands

Once the workflow completes successfully:

1. Click on the completed workflow run.
2. Scroll to the **Artifacts** section at the bottom of the summary page.
3. Download **`ApprazeAI-Windows-EXE`** — this is a ZIP archive containing the full `ApprazeAI` folder.

**Retention:** Artifacts are retained for **30 days** from the build date. Download a copy if you need longer-term storage.

## Testing the EXE on Windows

1. Extract the downloaded ZIP to a folder (e.g., `C:\ApprazeAI`).
2. Inside the extracted `ApprazeAI` folder, double-click **`ApprazeAI.exe`**.
3. **SmartScreen warning:** Because the binary is not code-signed, Windows will show "Windows protected your PC." Click **More info** → **Run anyway**. This is expected for unsigned builds.
4. **Expected behavior:**
   - A console window appears (this is normal — the EXE runs as a console application by design so you can see Streamlit logs).
   - Your default browser opens to `http://localhost:8501` within a few seconds.
   - If the browser opens before the server is ready, you may see a temporary connection error — refresh the page after 2–3 seconds.
5. To stop the app, close the console window. The browser tab will remain but the server will be unreachable.

## Troubleshooting

### EXE closes immediately / no browser opens

Run the EXE from an existing terminal window (`cmd` or PowerShell) instead of double-clicking. This keeps the window open so you can read the error output.

### "Failed to load script" or "Missing ScriptRunContext"

The bundled `app.py` may not be found. Verify that the `dist\ApprazeAI` folder contains `app.py` alongside the EXE. If missing, the `--add-data` path in the workflow may need adjustment.

### "ModuleNotFoundError" for a specific package

Add the missing module to `--hidden-import` flags in the workflow. Common candidates for Streamlit apps: `pandas._libs.tslibs`, `pyarrow`, or any dynamic import inside the app.

### Browser does not open automatically

The launcher calls `webbrowser.open()` before starting Streamlit. If it does not fire, manually navigate to `http://localhost:8501`. The server is still running.

### SmartScreen / antivirus flags the EXE

This is expected for unsigned PyInstaller binaries. For internal use, distribute the `--onedir` folder (not a single EXE) and instruct users to add an exclusion. For public distribution, a code signing certificate is required.

### EXE hangs or never starts the server

If the app uses `multiprocessing`, ensure `multiprocessing.freeze_support()` is the first call inside `if __name__ == "__main__":`. The wrapper generated by the workflow already includes this, but any code imported by `app.py` that spawns processes must also be safe under freeze.
